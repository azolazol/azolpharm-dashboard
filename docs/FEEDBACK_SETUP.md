# 문의 접수·이메일 알림 켜기

GitHub 화면은 업데이트되어 있습니다. Apps Script는 별도 시스템이므로 아래 설정과 배포 갱신이 필요합니다.

1. 저장소의 `apps-script/Code.gs` 전체로 Apps Script의 Code.gs를 교체하고 저장합니다.
2. `apps-script/appsscript.json` 전체로 매니페스트를 교체합니다. 기존 권한에 `script.send_mail` 발송 권한이 추가됩니다. Gmail 받은편지함 읽기 권한은 요청하지 않습니다.
3. 프로젝트 설정 → 스크립트 속성에 `FEEDBACK_TO`를 추가하고 알림을 받을 본인 이메일을 값으로 입력합니다. 수신 주소를 코드나 GitHub에 적지 않습니다. 기존 네이버·YouTube·시트 속성은 유지합니다.
4. 편집기에서 `setupFeedback`를 한 번 실행하고 이메일 발송 권한을 승인합니다. 비공개 FEEDBACK 시트가 생성되고 설정 확인 메일 1통이 발송됩니다. 실제 받은편지함 또는 스팸함에서 확인합니다.
5. 배포 → 배포 관리 → 현재 웹 앱 → 연필 → 버전: 새 버전 → 배포. 실행 사용자 ‘나’, 액세스 권한 ‘모든 사용자’를 유지합니다. 기존 배포를 수정하면 /exec 주소가 유지됩니다.
6. 대시보드를 새로고침하여 아래 문의 폼에 테스트 의견을 한 번 제출합니다. ‘접수되었습니다’ 표시와 FEEDBACK 행, 수신 메일을 확인합니다.

## 저장·보안·운영

- FEEDBACK 시트와 스크립트 편집 권한은 비공개로 유지합니다.
- 문의 유형, 내용, 답변 이메일(선택), 접수번호, 시각, 도배 제한용 브라우저 식별자의 해시, 발송 상태를 저장합니다.
- 메일 수신인은 스크립트 속성으로만 결정됩니다. 작성자가 외부 수신인을 지정할 수 없습니다.
- 답변 이메일은 작성자 입력값이며 소유 여부를 인증하지 않습니다. 해당 주소로 답장할 때 확인하세요.
- 문의 내용·이메일·수신인·식별자 해시는 공개 데이터 응답에 포함되지 않습니다. 임의 UUID 접수번호 조회는 접수 상태만 반환합니다.
- 동의 체크, 10~2,000자, 이메일 형식 검증, 숨겨진 봇 입력란, 브라우저별 분당 1건/하루 3건, 전체 하루 30건 제한. 브라우저 식별자를 바꾸는 공격까지 막는 CAPTCHA는 아니므로 잦은 악용 시 추가 방어가 필요합니다.
- 저장 후 알림을 보냅니다. 메일 오류가 있어도 문의는 보존되고 접수 완료로 표시됩니다.
- FEEDBACK의 mail_status가 SENT면 메일 발송 API가 성공한 상태입니다. 받은편지함 도착까지 보장하지는 않습니다.
- FAILED/PENDING은 원인을 해결한 뒤 편집기에서 `retryFeedbackEmails`를 실행하면 최대 10건 재시도합니다. SENDING/UNKNOWN은 중복 발송을 피하려 자동 재시도하지 않습니다. 수신함을 먼저 확인하세요.
- 설정을 끄려면 FEEDBACK_ENABLED를 false로 설정합니다. 문의 보관 자료는 운영자가 필요에 따라 삭제합니다. 자동 삭제는 적용하지 않았습니다.
- 기존 오전·오후 검색 수집 트리거를 추가하거나 변경할 필요는 없습니다.
